How the demo works

An identity document goes in. The AI reads it, the checks of the SOP run on what it read, the name is screened against compliance and sanctions lists, the AI suggests an outcome for every hit, and a person decides whatever the AI should not. Below: each step, what is plugged in today, and when a person takes over.

The workflow
three steps on every ID (read, check, screen), then the AI's review and the outcome; the amber line under each step is when a person takes over
1
Extraction

Read the ID

The AI reads every field as printed, the machine-readable zone (MRZ), and judges the photo: blurred, glare, cut off, covered.
Now: {{ reader_label }}
or Gemini, GPT, OCR, Azure: see "What plugs in"
→ A person when the ID cannot be read, or is not an identity document: nobody is screened.
2
SOP validation & fraud

Check the document

{{ n_checks }} checks in code on what was read: MRZ check digits, printed fields against the MRZ, expiry, age under {{ s.min_age }}, photo quality, missing or unsure fields. Beside them, the AI's own review of the document{% if review_rule %} ({{ review_rule|lower }}){% endif %}.
{% if idv_on %}Plus Didit: is the document genuine (screen captures, printed copies, a replaced portrait)?{% else %}Didit's genuine-document check: {{ 'connected, off for uploads' if dd_ready else 'ready for a key' }} (Settings){% endif %}
→ A person when a check fails or asks for a look{% if idv_on and s.auto_needs_idv %}, or Didit does not approve the document{% endif %}.
3
Compliance & sanctions

Screen the name

The name, date of birth and nationality are searched for sanctions, PEP and adverse-media records. The search only finds candidates; it never decides.
Now: {{ source_label }}
No match{% if s.auto_no_hit and s.auto_verify %}, and every check passed: the case can close by itself{% else %}: an analyst confirms it{% endif %}.
4
AI review

Decide each hit

The AI reads each hit under the screening SOP (version {{ sop.version }}) with {{ s.examples }} similar resolved cases, and suggests: clear it, a true match, ask the customer, or escalate, with a confidence and its reasons.
Now: {{ decider_label }}
→ A person when the AI is under {{ bar }}% sure or does not say false positive{% if s.auto_dob_differs %}, or the record's date of birth is the ID's{% endif %}{% if person_lists %}, and always for a {{ person_lists|join(' or ') }} record{% endif %}.
5
Human in the loop

The outcome

{% if s.auto_verify %}A case the rules call safe closes by itself (auto-verified). Every other case goes to an analyst, who has the final say on each hit: true positive, potential match or false positive, with a risk and a reason.{% else %}Auto-verify is off: an analyst decides every case, hit by hit, with the AI's suggestion beside each.{% endif %}
Analysts work the case page and the alert review; L2 / QC on Settings and the SOP
{% if s.auto_verify %}→ {{ qc }}% of the cases the AI would close stay with a person anyway, as a spot check of the AI.{% else %}→ A person on every case.{% endif %}
How the AI is asked
two calls per case; the rules around them are code and Settings, so the AI never decides alone
{{ icon('zoom-in') }} Call 1 · Read the ID
Sent

Returned
The document type and country, each field as printed, the MRZ lines, the fields it is unsure of, any photo problem, and its review: is the document complete and consistent for its type, and if not, why.
Then
